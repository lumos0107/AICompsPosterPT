## 1. 사용자 결정 (11/10, 원문 요지)

1. 반경은 '20m + 20m에 안 붙은 묶음만 30m 안 가장 가까운 노드 하나'. 영상 확인 뒤 정한 규칙이라고 기록하고, 이 규칙으로 붙는 작은 삼거리·횡단보도 신호 4곳도 적는다.
2. 출발점은 탑동을 그대로 두고 범위를 북쪽으로 넓힌다. 33.515 북쪽에 도로 44.7km가 잘려 있고, 그중 38.3km가 바로 위 줄 13칸에 있다(사용자 확인). 매립지·해안도로·원도심 북쪽이 빠진 것이다.
3. 북쪽 줄, 그 위로 도로가 있는 칸, 북서쪽 빈 3칸의 도엽 번호를 정리한다. **받을 때 로그인은 사용자가 한다.**
4. 받은 뒤 도엽 시점을 확인하고 그래프 자르기, 신호 묶음, 부착 80%, 출발점 표를 넓힌 범위로 다시 잰다.
5. 신호 위치의 근거는 부착률 대신 신호기현황 대조로 쓴다. 무작위 도로 점 값은 고른 추출로 다시 재서 옆에 적는다.
6. 서귀포가 빠져 '두 시 차이' 점검을 못 하는 것은 한계로 적는다. 범위 밖 방향을 안내점에서 빼는 코드 수정은 진행해도 된다.
7. 이전 지시 유지: 원본 지도 파일 외부 업로드 금지, ITS 키가 오면 교체 여부를 그때 묻기, 마감 미정.

## 3. 받은 뒤 할 일 (순서)

1. 압축을 `데이터/원본/국토정보맵/수치지형도_1000_표본/제주도심_북쪽27장/`에 두고 풀기(형식이 SHP인지 NGI인지 확인). 도엽별 xml에서 촬영·제작년도 확인.
2. 신호등(C0493376)·신호등제어기(C0503375, 구분 IUD002) 점을 `check_signals.py` 방식으로 읽어 `신호1000_<접미사>.csv`(열: 지역, 도엽, 형식, 종류, 용도, x5179, y5179)로 저장. 도엽 경계 중복(1m) 제거.
3. 칸 목록 `실험범위_122칸.txt`(95 + 27) 만들기.
4. `cut_jeju.py`를 칸 목록 파일을 받게 고쳐 그래프 자르기·주 요소 비율·출발점 표를 다시 잼. **주의: npz 배열은 반복문 밖에서 한 번만 읽을 것**(접근할 때마다 다시 풀어 매우 느림).
5. `signal_nodes.py <그래프.npz> 실험범위_122칸.txt 122칸`으로 신호 노드·부착률·신호기현황 대조 다시 잼.
6. 넓힌 범위에서 20~30m 사이 묶음이 새로 생기면 같은 방식으로 영상 확인.
7. 그다음 코드 수정 나머지(비용 단위, 귀환 구간 선호, 재사용 판정, 시설 항, 교량 양 끝 고도 보간, 새 그래프 DB 넣기) → 예비 경로 → 3장 나 점검(경사 50·100·200m, 세 선호 값) → 경로 교차 영상 확인 → 8장 최종 판단 → 사용자 확인 → 본 실험 → 본 실험 경로 교차 영상 확인 → 초안 고치기.

## 4. 확인 못 한 것

1. 20~30m 묶음 27곳의 큰·중간·작은 구분은 Claude 단독 영상 판정.
2. 변환 위치가 1:1,000에서 50m 넘게 떨어진 7건의 원인.
3. 30m에도 안 붙는 묶음 20곳의 성격.
4. 북쪽 33.515 위 도로 길이가 사용자 값과 조금 다름(44.8 대 44.7km, 38.8 대 38.3km). 칸 배정 방식 차이로 추정.
5. 편의시설·고도는 제주 전체로 만들었고, 실험 범위 안의 건수는 아직 세지 않았다.
